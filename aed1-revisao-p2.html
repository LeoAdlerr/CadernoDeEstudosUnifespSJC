Alocar um nó

typedef struct No {
    int dado;            // chave inteira guardada no nó
    struct No *esq;      // raiz da subárvore esquerda (NULL = vazia)
    struct No *dir;      // raiz da subárvore direita  (NULL = vazia)
} No;

No *novo_no(int dado) {
    No *n = malloc(sizeof(No));   // sizeof(No), nunca sizeof(No *)
    if (n == NULL) return NULL;   // sem memória: devolve NULL
    n->dado = dado;
    n->esq = NULL;                // malloc NÃO zera: inicialize sempre
    n->dir = NULL;
    return n;                     // o endereço sobrevive ao fim da função
}

Limpeza total: sempre em pós-ordem

Um nó só pode ser liberado depois dos filhos, porque é ele quem guarda os endereços deles. Liberar a raiz primeiro e depois ler r->esq é uso de memória já devolvida.

void destroi_arvore(No *r) {
    if (r == NULL) return;        // caso base: nada a liberar
    destroi_arvore(r->esq);       // 1º libera toda a esquerda
    destroi_arvore(r->dir);       // 2º libera toda a direita
    free(r);                      // 3º só agora libera a raiz (pós-ordem)
}

Fila dinâmica (FIFO)

Entra no fim, sai do início. É a estrutura obrigatória do percurso em nível (Módulo 3): os nós saem na mesma ordem em que foram descobertos. Aqui ela já guarda No *, pronta para a árvore.

typedef struct Cel {
    No *no;                // a fila guarda PONTEIROS para nós da árvore
    struct Cel *prox;
} Cel;

typedef struct {
    Cel *ini;              // de onde se retira
    Cel *fim;              // onde se insere
} Fila;

void fila_inicia(Fila *f) { f->ini = NULL; f->fim = NULL; }

int fila_vazia(Fila *f) { return f->ini == NULL; }

void enfileira(Fila *f, No *no) {
    Cel *c = malloc(sizeof(Cel));       // nova célula na Heap
    c->no = no;
    c->prox = NULL;                     // será a última
    if (f->fim == NULL) f->ini = c;     // fila vazia: também é a primeira
    else f->fim->prox = c;              // senão, engata após a última
    f->fim = c;                         // fim passa a ser a nova célula
}

No *desenfileira(Fila *f) {             // pré-condição: fila não vazia
    Cel *c = f->ini;                    // célula que vai sair
    No *no = c->no;                     // salva o conteúdo ANTES do free
    f->ini = c->prox;                   // início avança
    if (f->ini == NULL) f->fim = NULL;  // esvaziou: fim também vira NULL
    free(c);                            // libera a célula (não o nó da árvore)
    return no;
}

Armadilhas clássicas de prova em papel

  • malloc(sizeof(No *)) reserva só o tamanho de um ponteiro. O certo é sizeof(No).
  • *r->esq significa *(r->esq). Com ponteiro duplo, escreva sempre (*r)->esq.
  • Usar . com ponteiro ou -> com variável comum. Ponteiro pede seta.
  • Nó novo sem esq = dir = NULL: malloc devolve lixo e o percurso não para nunca.
  • free(r) antes das chamadas recursivas em destroi_arvore.
  • Em desenfileira, esquecer f->fim = NULL quando a fila esvazia: o próximo enfileira escreve em célula já liberada.
  • Em desenfileira, dar free(c) e depois ler c->no ou c->prox. Salve antes.

1Análise assintótica (Big O)

Quanto o número de instruções cresce quando a entrada cresce. Constantes e termos menores são descartados.

Definição enxuta

f(n) = O(g(n)) se existem constantes c > 0 e n0 tais que f(n) ≤ c·g(n) para todo n ≥ n0. Ou seja, g é um limite superior assintótico de f. Na disciplina, f(n) costuma ser a contagem de instruções no pior caso.

Exemplo: f(n) = 3n + 3 é O(n), pois 3n + 3 ≤ 4n para todo n ≥ 3 (c = 4, n0 = 3).

Regras de simplificação: fique com o termo de maior crescimento e apague o coeficiente. Ordem de crescimento: 1 < log n < n < n log n < n² < 2n.

Contagem de frequência de instruções

Cada atribuição, comparação e incremento conta 1. Um for se decompõe em três partes: inicialização (1 vez), teste (n + 1 vezes, pois o último teste é o que falha) e incremento (n vezes).

Convenção. Há professores que contam soma += v[i] como 2 operações ou ignoram o teste do laço. O Big O final não muda, mas a função f(n) muda: use na prova a mesma convenção dos slides da sua turma.

Laço simples: O(n)

soma = 0;                      // 1
for (i = 0; i < n; i++)        // i = 0: 1   |  i < n: n + 1  |  i++: n
    soma += v[i];              // n

f(n) = 1 + 1 + (n + 1) + n + n = 3n + 3, portanto O(n).

Laços aninhados: O(n²)

soma = 0;                      // 1
for (i = 0; i < n; i++)        // 1  |  n + 1  |  n
    for (j = 0; j < n; j++)    // j = 0: n  |  j < n: n(n + 1)  |  j++: n²
        soma++;                // n²

O laço interno inteiro roda n vezes; em cada rodada o teste j < n ocorre n + 1 vezes.

f(n) = 1 + 1 + (n + 1) + n + n + n(n + 1) + n² + n² = 3n² + 4n + 3, portanto O(n²).

Variável dividida por 2: O(log n)

c = 0;                         // 1
for (i = n; i > 1; i /= 2)     // i vale n, n/2, n/4, ..., 1
    c++;                       // executa k vezes, com n / 2^k = 1

Depois de k voltas, i = n / 2k. O laço para quando n / 2k = 1, isto é, 2k = n e k = log2 n. O mesmo vale para i = 1; i < n; i *= 2.

Busca linear × busca binária

int busca_linear(const int *v, int n, int x) {
    for (int i = 0; i < n; i++)      // pior caso: x não está, n comparações
        if (v[i] == x) return i;
    return -1;
}

Linear. No pior caso (elemento ausente) faz n comparações com x: O(n). Não exige ordenação.

Binária. Exige vetor ordenado. Cada comparação descarta metade do que resta:

PassoElementos restantes
0n
1n / 2
2n / 4 = n / 2²
kn / 2k

A busca termina quando resta 1 elemento: n / 2k = 1 ⇒ 2k = n ⇒ k = log2 n. Logo o pior caso é O(log n); com exatidão, no máximo ⌊log2 n⌋ + 1 comparações. Para n = 1.000.000: 1.000.000 comparações na linear contra 20 na binária.

Armadilhas clássicas de prova em papel

  • Contar o teste do for como n vezes. São n + 1.
  • Responder O(3n² + 4n). A resposta final é só O(n²).
  • Ver dois laços e escrever O(n²) sem olhar o passo: com j *= 2 o laço interno é log n.
  • Dizer que a busca em ABB é O(log n) “no pior caso”. No pior caso a árvore é uma lista: O(n).
  • Aplicar busca binária em vetor não ordenado.
  • Pedir a função f(n) e você entregar só o Big O, ou o contrário. Leia o que a questão pede.

2Busca binária recursiva e LAB 8

Dois casos base, duas chamadas recursivas e nenhum laço.

Implementação padrão

/* Devolve o índice de x em v[ini..fim] ou -1 se não existir */
int busca_bin(const int *v, int ini, int fim, int x) {
    if (ini > fim) return -1;                 // intervalo vazio: não achou
    int meio = ini + (fim - ini) / 2;         // ponto médio (sem estouro de int)
    if (v[meio] == x) return meio;            // achou
    if (x < v[meio])
        return busca_bin(v, ini, meio - 1, x);    // metade esquerda, SEM o meio
    return busca_bin(v, meio + 1, fim, x);        // metade direita,  SEM o meio
}

Chamada inicial: busca_bin(v, 0, n - 1, x). A cada chamada o intervalo perde pelo menos o elemento do meio, então a recursão sempre termina.

v = [10  20  30  40  50  60  70]      x = 60
      0   1   2   3   4   5   6

busca_bin(v, 0, 6, 60)   meio = 3   v[3] = 40 < 60   vai para a direita
busca_bin(v, 4, 6, 60)   meio = 5   v[5] = 60        achou: devolve 5

Para x = 65:  (0,6) -> (4,6) -> (6,6) -> (6,5)   ini > fim: devolve -1

LAB 8: entre quais itens x se encaixa

Enunciado: dada uma lista ordenada A com n inteiros e um inteiro x que não está na lista, encontrar A[i] e A[i+1] tais que A[i] < x < A[i+1], ou informar que o par não existe. Exigências: algoritmo recursivo baseado em busca binária, nenhuma variável global, toda memória desalocada.

Formato
Entrada, linha 1o item x e o tamanho n, nessa ordem
Entrada, linha 2os n inteiros da sequência, já ordenados
Saídaos dois inteiros do intervalo, ou a frase nao ha intervalo valido (sem acentos)

Não conferido. O enunciado não mostra um exemplo, então não há como saber se os dois inteiros saem separados por espaço, colados ou em linhas diferentes. O programa abaixo imprime 20 30, com um espaço. Se o juiz recusar só por formatação, é esse printf que deve mudar.

Ideia. Manter um invariante: v[ini] < x < v[fim]. As bordas são verificadas uma única vez, antes da recursão. Dentro dela, o meio substitui uma das bordas e o invariante continua valendo. Quando as bordas ficam vizinhas, a resposta é ini.

/*
 * AED I - Laboratório VIII: intervalo de x em lista ordenada (busca binária recursiva)
 * Nome: ...                RA: ...
 * Entrada: x e n na primeira linha; os n inteiros ordenados na segunda
 * Saída:   os dois vizinhos de x ou "nao ha intervalo valido"
 */
#include <stdio.h>
#include <stdlib.h>

/* Invariante: v[ini] < x < v[fim] e ini < fim.
   Devolve i tal que v[i] < x < v[i+1], ou -1 se x está no vetor. */
int intervalo_rec(const int *v, int ini, int fim, int x) {
    if (fim - ini == 1) return ini;           // vizinhos: o intervalo é (v[ini], v[fim])
    int meio = ini + (fim - ini) / 2;         // ini < meio < fim, garantido
    if (v[meio] == x) return -1;              // defesa: o enunciado garante que não ocorre
    if (v[meio] < x)
        return intervalo_rec(v, meio, fim, x);    // meio vira a nova borda esquerda
    return intervalo_rec(v, ini, meio, x);        // meio vira a nova borda direita
}

/* Trata as bordas e só então dispara a recursão */
int intervalo(const int *v, int n, int x) {
    if (n < 2) return -1;                     // lista vazia ou unitária
    if (x <= v[0]) return -1;                 // menor (ou igual) ao primeiro
    if (x >= v[n - 1]) return -1;             // maior (ou igual) ao último
    return intervalo_rec(v, 0, n - 1, x);     // aqui v[0] < x < v[n-1]
}

int main(void) {
    int x, n;
    if (scanf("%d %d", &x, &n) != 2) return 0;   // 1ª linha: o item e o tamanho
    int *v = NULL;
    if (n > 0) {
        v = malloc(n * sizeof(int));              // vetor na Heap, tamanho lido
        if (v == NULL) return 1;
        for (int i = 0; i < n; i++) scanf("%d", &v[i]);   // 2ª linha: a sequência
    }

    int i = intervalo(v, n, x);                   // n < 2 já devolve -1 sem tocar em v
    if (i == -1) printf("nao ha intervalo valido\n");
    else printf("%d %d\n", v[i], v[i + 1]);

    free(v);                                      // free(NULL) é permitido e não faz nada
    return 0;
}

Por que aqui é meio e não meio ± 1? Na busca clássica o meio já foi testado e pode ser descartado. Aqui o meio vira borda do intervalo e precisa continuar dentro dele. A recursão ainda termina porque ini < meio < fim sempre que fim - ini ≥ 2.

Armadilhas clássicas de prova em papel

  • Esquecer o caso base ini > fim: recursão infinita quando o elemento não existe.
  • Esquecer o return na frente da chamada recursiva. A função acha o valor e devolve lixo.
  • Na busca clássica, chamar com meio em vez de meio - 1 ou meio + 1: com dois elementos o intervalo não encolhe.
  • Comparar índice com valor: if (meio == x) no lugar de if (v[meio] == x).
  • No juiz: ler n antes de x (a ordem na entrada é x, depois n), escrever a frase com acento, ou esquecer o free(v).
  • Resolver com laço. O enunciado zera soluções não recursivas.

3. Pós-ordem, iterativo

Sem recursão, a pilha é sua. A dificuldade do pós-ordem é que cada nó aparece no topo duas vezes: ao voltar da esquerda e ao voltar da direita. O ponteiro ultimo diz de onde se está voltando.

  1. Enquanto houver nó, empilhe e desça para a esquerda.
  2. Acabou a esquerda: olhe o topo sem desempilhar.
  3. Se o topo tem direita e ela não foi a última visitada, vá para a direita.
  4. Caso contrário, visite o topo, desempilhe e registre-o em ultimo.
/* Pilha encadeada reaproveitando a struct Cel da fila */
void empilha(Cel **topo, No *no) {
    Cel *c = malloc(sizeof(Cel));
    c->no = no;
    c->prox = *topo;           // nova célula aponta para o topo antigo
    *topo = c;                 // e passa a ser o topo
}

No *desempilha(Cel **topo) {   // pré-condição: pilha não vazia
    Cel *c = *topo;
    No *no = c->no;
    *topo = c->prox;
    free(c);
    return no;
}

void pos_ordem_iter(No *r) {
    Cel *pilha = NULL;                 // pilha vazia
    No *atual = r;
    No *ultimo = NULL;                 // último nó que foi impresso
    while (atual != NULL || pilha != NULL) {
        if (atual != NULL) {
            empilha(&pilha, atual);    // guarda o caminho

void em_ordem_seco(No *r, int *primeiro) {

Armadilhas clássicas de prova em papel

  • Função recursiva sem if (r == NULL) return; na primeira linha.
  • Trocar a posição do printf: é ela, e só ela, que define o percurso.
  • Fazer o percurso em nível com pilha ou com recursão simples. Sai um percurso em profundidade.
  • Enfileirar filhos NULL e depois acessar n->dado.
  • Enfileirar a direita antes da esquerda: o nível sai invertido.
  • No pós-ordem iterativo, esquecer o teste topo->dir != ultimo: laço infinito entre o nó e sua direita.
  • Na busca, esquecer o return das chamadas recursivas.

4ABB: inserção e remoção (LAB 10)

Propriedade que toda operação precisa preservar: para cada nó, tudo à esquerda é menor e tudo à direita é maior.

Propriedade da ABB

esq < raiz < dir, valendo para a subárvore inteira e não só para os filhos diretos. Consequência: o percurso em ordem sai crescente. Nestas notas, chaves repetidas são ignoradas na inserção; se o enunciado disser outra coisa, mude o else if para else.

Inserção recursiva

Versão padrão: ponteiro simples, devolve a raiz

No *insere(No *r, int x) {
    if (r == NULL) return novo_no(x);     // achou a vaga: o novo nó é a "raiz" daqui
    if (x < r->dado)
        r->esq = insere(r->esq, x);       // religa a esquerda com o que voltar
    else if (x > r->dado)
        r->dir = insere(r->dir, x);       // religa a direita com o que voltar
    /* x == r->dado: repetido, ignora */
    return r;                             // devolve a raiz desta subárvore
}

Versão alternativa: ponteiro duplo, sem retorno

void insere_pp(No **r, int x) {
    if (*r == NULL) {                     // *r é o ponteiro que está "vago"
        *r = novo_no(x);                  // escreve direto no campo do pai
        return;
    }
    if (x < (*r)->dado)
        insere_pp(&(*r)->esq, x);         // passa o ENDEREÇO do campo esq
    else if (x > (*r)->dado)
        insere_pp(&(*r)->dir, x);         // passa o ENDEREÇO do campo dir
}

As duas fazem o mesmo. Na primeira quem religa é a atribuição r->esq = insere(...); na segunda é a escrita em *r. Na prova, escolha uma e não misture.

Caso 1: folha

Sucessor = um passo à direita, depois tudo à esquerda. Ele nunca tem filho esquerdo.

Remoção recursiva

Mesma lógica de religação da inserção: cada chamada devolve a nova raiz da subárvore. Os casos 1 e 2 se fundem: se não há filho esquerdo, devolve o direito (que pode ser NULL).

No *minimo(No *r) {                        // pré-condição: r != NULL
    while (r->esq != NULL) r = r->esq;     // o menor está o mais à esquerda
    return r;
}

No *remove_no(No *r, int x) {
    if (r == NULL) return NULL;                    // x não está na árvore
    if (x < r->dado) {
        r->esq = remove_no(r->esq, x);             // procura à esquerda e religa
    } else if (x > r->dado) {
        r->dir = remove_no(r->dir, x);             // procura à direita e religa
    } else {                                       // achou: r é o nó a remover
        if (r->esq == NULL) {                      // casos 1 e 2 (sem filho esq)
            No *filho = r->dir;                    // pode ser NULL (folha)
            free(r);
            return filho;                          // o pai passa a apontar p/ o neto
        }
        if (r->dir == NULL) {                      // caso 2 (só filho esq)
            No *filho = r->esq;
            free(r);
            return filho;
        }
        No *suc = minimo(r->dir);                  // caso 3: sucessor em ordem
        r->dado = suc->dado;                       // copia o valor (r NÃO é liberado)
        r->dir = remove_no(r->dir, suc->dado);     // remove o sucessor (cai no caso 1 ou 2)
    }
    return r;
}

Remoção iterativa

O truque é andar com um No **p que aponta para o campo por onde se chega ao nó atual: no começo é a própria raiz, depois o esq ou dir do pai. Assim *p = ... religa o pai sem precisar de variável pai nem de caso especial para a raiz.

int remove_iter(No **raiz, int x) {
    No **p = raiz;                    // p = endereço do ponteiro que chega ao nó atual
    while (*p != NULL && (*p)->dado != x) {
        if (x < (*p)->dado) p = &(*p)->esq;    // desce guardando o campo do pai
        else p = &(*p)->dir;
    }
    if (*p == NULL) return 0;         // não encontrou: nada removido

    No *alvo = *p;                    // nó que contém x
    if (alvo->esq != NULL && alvo->dir != NULL) {   // caso 3
        No **ps = &alvo->dir;                       // um passo à direita...
        while ((*ps)->esq != NULL) ps = &(*ps)->esq;   // ...e tudo à esquerda
        alvo->dado = (*ps)->dado;     // copia o valor do sucessor
        p = ps;                       // agora quem sai fisicamente é o sucessor
        alvo = *ps;                   // (ele tem no máximo o filho direito)
    }
    /* aqui alvo tem 0 ou 1 filho (casos 1 e 2) */
    if (alvo->esq != NULL) *p = alvo->esq;   // pai herda o único filho...
    else *p = alvo->dir;                     // ...ou NULL, se era folha
    free(alvo);
    return 1;                         // removeu
}

Cada nó pode ter qualquer número de filhos. Em C, dois ponteiros por nó bastam.

Conceito

O grau de um nó é o número de filhos; o grau da árvore é o maior grau entre os nós. Como o grau não é conhecido de antemão, um vetor fixo de filhos desperdiça memória ou limita a árvore. A saída clássica é guardar os filhos de um nó em uma lista encadeada.

6Grafos e digrafos

Vértices ligados por arestas, sem raiz e sem hierarquia. A escolha da representação define o custo de cada operação.

Definições

  • Grafo G = (V, E): V é o conjunto de vértices e E o de arestas, pares de vértices.
  • Não direcionado: a aresta {u, v} vale nos dois sentidos. Digrafo: o arco (u, v) sai de u e chega em v.
  • Adjacência: v é adjacente a u se existe aresta de u para v.
  • Grau: número de arestas incidentes no vértice. Em digrafos há grau de saída e grau de entrada.
  • Soma dos graus de um grafo não direcionado: 2|E|. Em um digrafo, soma das saídas = soma das entradas = |E|.
  • Caminho: sequência de vértices em que cada par consecutivo é ligado por aresta. Ciclo: caminho que volta ao início.
  • Conexo: existe caminho entre qualquer par de vértices. Em digrafos, fortemente conexo exige caminho nos dois sentidos.
  • Máximo de arestas sem laços: |V|(|V| − 1)/2 no não direcionado; |V|(|V| − 1) no digrafo.

typedef struct Aresta {
    int v;                     // vértice de destino
    struct Aresta *prox;       // próximo vizinho na lista
} Aresta;

typedef struct {
    int V;                     // número de vértices
    Aresta **adj;              // adj[u] = cabeça da lista de vizinhos de u
} Grafo;

Grafo *cria_grafo(int V) {
    Grafo *g = malloc(sizeof(Grafo));
    g->V = V;
    g->adj = calloc(V, sizeof(Aresta *));    // V cabeças, todas NULL
    return g;
}

void insere_arco(Grafo *g, int u, int v) {   // direcionado: u -> v
    Aresta *a = malloc(sizeof(Aresta));
    a->v = v;
    a->prox = g->adj[u];       // novo aponta para a cabeça antiga
    g->adj[u] = a;             // inserção no INÍCIO: O(1)
}

void insere_aresta(Grafo *g, int u, int v) { // não direcionado: u — v
    insere_arco(g, u, v);
    insere_arco(g, v, u);      // a mesma aresta aparece nas duas listas
}

int adjacente_l(Grafo *g, int u, int v) {
    for (Aresta *a = g->adj[u]; a != NULL; a = a->prox)
        if (a->v == v) return 1;             // v está na lista de u
    return 0;                                // custo O(grau(u))
}

void libera_grafo(Grafo *g) {
    for (int u = 0; u < g->V; u++) {
        Aresta *a = g->adj[u];
        while (a != NULL) {
            Aresta *prox = a->prox;          // salva o próximo ANTES do free
            free(a);
            a = prox;
        }
    }
    free(g->adj);                            // depois o vetor de cabeças
    free(g);                                 // por último a struct
}

No grafo não direcionado cada aresta gera dois nós de lista, um em cada extremidade. No digrafo, use só insere_arco.

Um grafo não direcionado tem 7 arestas. Quanto vale a soma dos graus?

14. Cada aresta soma 1 ao grau de cada uma de suas duas pontas.

Grafo com 1000 vértices e 2000 arestas: matriz ou listas?

Listas. A matriz teria 1.000.000 de posições para guardar 2000 arestas; as listas usam espaço proporcional a |V| + |E|.

O que acontece se insere for chamada como insere(raiz, x); com a árvore vazia?

O nó é criado e devolvido, mas ninguém guarda o retorno: raiz continua NULL e o nó vaza. O certo é raiz = insere(raiz, x);.
